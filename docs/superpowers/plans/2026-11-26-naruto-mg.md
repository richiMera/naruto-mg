# naruto-mg Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Gestionale privato per due membri (collezione comune di box, sealed e carte, acquisti, vendite, preordini, negozi, saldo "chi deve a chi") con vetrina pubblica, frontend su GitHub Pages e backend Supabase.

**Architecture:** SPA Vite + React + TS servita da GitHub Pages sotto `/naruto-mg/`, routing hash. Tutta la logica che tocca soldi o più tabelle vive in Postgres (RPC `security invoker` transazionali + view `security_invoker`), protetta da RLS basata su `private.is_member()`. Il frontend chiama Supabase direttamente con la chiave anon.

**Tech Stack:** Vite, React 18, TypeScript, Mantine 7 (`@mantine/core`, `form`, `dates`, `charts`, `notifications`), React Router 6 (`createHashRouter`), TanStack Query 5, `@supabase/supabase-js` 2, Vitest + Testing Library + jsdom, Supabase CLI (Postgres locale via Docker, test pgTAP con `supabase test db`), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-26-naruto-mg-design.md`

## Global Constraints

- Importi sempre in centesimi interi (`bigint` in DB, `number` intero in TS), solo EUR. Mai float per i soldi.
- Ogni ripartizione di centesimi (spedizione, commissioni, costo box, prezzo preordine) usa il metodo del resto maggiore: la somma delle parti è **esattamente** il totale.
- Ripartizioni tra membri in punti base (`share_bp`), somma 10000 per movimento; default 50/50.
- RLS attiva su ogni tabella `public`; policy solo `to authenticated` con `(select private.is_member())`. Nessun grant di tabella ad `anon`. Unica cosa eseguibile da `anon`: `public.get_showcase()`.
- Views con `security_invoker = true`. RPC operative `security invoker`; solo `private.is_member()` e `get_showcase()` sono `security definer` con `set search_path = ''`.
- Mai la chiave `service_role` nel repo o nel bundle. Env frontend: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`.
- Base path Vite `/naruto-mg/`; router hash.
- Interfaccia interamente in italiano; date mostrate `dd/MM/yyyy`; importi `€ 1.234,56` (`Intl.NumberFormat('it-IT', { style: 'currency', currency: 'EUR' })`).
- Una riga `items` per copia fisica; l'interfaccia offre "copie: N".
- Prerequisiti locali: Node 20+, Docker attivo, Supabase CLI.

## Review Focus

1. **Centesimi indivisibili** (es. spedizione 1000 su 3 righe da prezzo uguale): le quote devono sommare esattamente al totale → test `allocate_cents` in Task 2 e test RPC in Task 4/5.
2. **Vendere un articolo già venduto o una box aperta** (doppio click, due membri in contemporanea): l'RPC deve rifiutare con errore leggibile → test in Task 5.
3. **Importi digitati all'italiana** (`12,50`, `1.234,5`, `12.5`, spazi, `€`): devono diventare centesimi corretti; input vuoto o non numerico → errore di form, non 0 → test in Task 7.
4. **Utente autenticato ma non membro** (account creato per errore): vede "Account non autorizzato" e nessun dato, non una pagina vuota → test pgTAP in Task 2 e test UI in Task 8.
5. **Supabase in pausa / rete assente**: le pagine mostrano un messaggio d'errore con "Riprova", non uno spinner infinito → test in Task 8 sul componente `QueryState`.
